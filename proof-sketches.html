Why a dominated action can be removed without guessing beliefs

Ordinary claim: If one action does worse than another no matter what the other side does, the weak action does not need a story about what the other side is likely to do.

Minimal setup: One player has at least two available actions. For every relevant action by the opponent, one of the player's actions gives at least as much payoff as the other, and for at least one opponent action it gives strictly more.

Proof idea: The proof is just an all-cases comparison. Imagine the opponent's move is revealed after you choose. In every possible case you would be no worse with the dominating action, and in some case you would be better. Since there is no case where the dominated action helps, no belief about the opponent can rescue it.

Mathematical move: For strict dominance, show u_i(A, other_action) > u_i(B, other_action) for every other_action (strict in every case). The weaker version replaces > with >= everywhere plus a strict inequality somewhere. Either way the comparison must pass in every column or branch being considered.

Why it matters: This result lets the reader safely simplify a strategic problem before solving for equilibrium. It matters because safe deletion is different from deleting an option that merely seems unlikely or unattractive in one guessed scenario.

Where it breaks: The argument fails if the comparison ignores some opponent action, if payoffs were mapped incorrectly, or if deletion changes the game in a way the model did not justify. It also does not say the remaining action is globally good; it only says the removed action was never needed.

Proof-reading move: When reading this proof, do not start by asking what the opponent will probably do. Start by drawing the full list of opponent actions as columns or branches. Then compare the two candidate actions row by row using the same opponent action each time. If one action wins or ties in every row and wins somewhere, the proof is finished because there is no belief that puts weight on a rescuing row.

Student trap: The common trap is to delete an action because it feels implausible, embarrassing, or unlikely in the story. That is not dominance. Dominance is stronger: even if the opponent did the most inconvenient listed thing, the deleted action would still not help. Another trap is forgetting that weak dominance can be delicate when deletion is repeated, because removing one action may change what later comparisons mean.

Rebuild check: To rebuild the proof from scratch, name the two actions, name the outside cases, and write one payoff comparison for each case. If any case makes the supposedly dominated action strictly better, stop and downgrade the claim to a belief-based or equilibrium-based argument. If all cases pass, say exactly whether the dominance is strict or weak before using it for iterated deletion.

Why the move is legitimate: The all-cases comparison is legitimate because a belief over opponent actions is only a way of putting weights on those cases. If action A is never worse than action B in any case, no set of weights can make B better. The hidden requirement is that the list of cases is complete for the model. If the opponent has an unlisted action or the payoff mapping is wrong, the proof has compared the wrong universe.

Why risky choices need weighted payoffs, not a single imagined outcome

Ordinary claim: When the result is uncertain, a choice must be judged before knowing which possible world will happen, so the model needs a way to compare whole risky prospects rather than one imagined outcome.

Minimal setup: An actor chooses among actions. Each action can lead to several outcomes, each outcome has a payoff, and the model assigns probabilities to those outcomes.

Proof idea: The proof idea is averaging before the uncertainty resolves. If one action gives a high payoff only in a rare case and another gives a moderate payoff often, the actor needs one number that respects both payoff size and likelihood. Expected utility is that disciplined weighted average.

Mathematical move: E[u] = sum over outcomes of probability(outcome) times utility(outcome). Each term asks how much a possible world matters before it is known: bigger payoff matters more, and higher probability matters more.

Why it matters: This result makes uncertainty part of the choice rather than something discussed after the fact. It is the bridge from preference over finished outcomes to choice among risky actions, auctions, mixed strategies, and Bayesian games.

Where it breaks: The argument depends on the chosen utility scale and probability model. If the actor cares about risk in a way the utility function omits, or if the probabilities are not justified, the expected-utility calculation can look precise while measuring the wrong thing.

Proof-reading move: Read the proof as a timing argument. The person must choose before the uncertainty is resolved, so the calculation cannot use the outcome that happens later. It must value the whole lottery now. The weighted average is not pretending every outcome partly happens; it is a bookkeeping device for a decision made while several futures are still possible.

Student trap: The common trap is to replace the lottery with a vivid story about the best case, worst case, or most likely case. That throws away part of the prospect. Another trap is to treat utility as money automatically. If the person is risk averse, one more dollar in a bad state may matter more than one more dollar in a comfortable state, so the utility scale has to be named before averaging.

Rebuild check: To rebuild the proof, list the possible outcomes, attach one probability to each, attach one utility number to each, and multiply before adding. Then ask two audit questions: do the probabilities describe the uncertainty the chooser actually faces, and does the utility scale represent what the chooser actually cares about? If either answer is weak, the formula may be correct but the model is not yet earned.

Why the move is legitimate: The weighted-average move is legitimate only after the model has chosen probabilities and a utility scale. Probabilities say how much each possible world should count before the outcome is known; utility says what each world is worth to the chooser. Multiplying and adding is not a moral claim that averages are always fair. It is valid for this model because the decision is made before uncertainty resolves and because the utility representation is the object being averaged.

Why Nash equilibrium is a mutual no-deviation check

Ordinary claim: A proposed behavior pattern is stable only if every participant, looking at the others' behavior as fixed, has no better individual move.

Minimal setup: There are players, each player has actions or strategies, and each player has payoffs for every full combination of choices.

Proof idea: The proof idea is circular consistency. Start with a proposed outcome. Take one player at a time and freeze everyone else. If that player can improve by switching, the proposal cannot be stable. If every player fails to find a profitable switch, the proposal survives the local pressure created by all the others.

Mathematical move: For every player i, the chosen action a_i must belong to BR_i(a_-i). In words, player i's action is one of the best responses to the other players' actions. The condition must hold for all players at once.

Why it matters: Nash equilibrium gives the course a reusable stability test for simultaneous strategic dependence. It matters because strategic choice is not about finding one best action in isolation; it is about fitting several local best-response checks together.

Where it breaks: The result does not promise fairness, efficiency, uniqueness, or real-world convergence. It also becomes too weak for dynamic or private-information problems unless the model adds later-history or belief consistency checks.

Proof-reading move: Read the proof as a failed-deviation search. A proposed equilibrium is not proven by saying the outcome looks reasonable. It is proven by taking each player aside, holding the other players fixed exactly as proposed, and asking whether that one player has a better listed move. The word mutual matters: every local no-improvement test must point back to the same profile. If two players would both like to move together, that may be socially important, but it is not the deviation Nash is checking.

Student trap: The common trap is to treat equilibrium as good social design. A Nash equilibrium can be inefficient, unfair, or ugly; the proof only says no single player can improve by moving alone. A second trap is to forget the action menu. If a profitable deviation was omitted from the model, the no-deviation check passed only because the model hid the move.

Rebuild check: To rebuild the proof, choose a candidate profile and write one best-response check per player. For player i, freeze a_-i and compare every available a_i. If the candidate action is tied for best or strictly best for every player, the profile survives. If one player can improve, record that deviation instead of trying to rescue the candidate with a story about intentions.

Why the move is legitimate: Freezing the other players is legitimate because Nash equilibrium is deliberately a one-person deviation test. It asks whether the proposed profile can resist local pressure from any single player changing alone. That does not mean joint deviations are unimportant; it means they are outside this solution concept. The hidden requirement is that each player's action set contains the relevant unilateral alternatives. If the menu is incomplete, the no-deviation proof is too easy.

Why a future threat must be tested from the future

Ordinary claim: A threat or promise made early is credible only if carrying it out later will still be attractive when the later decision point arrives.

Minimal setup: A game has a sequence of choices. At least one player moves after seeing an earlier action, and the later player has more than one possible response.

Proof idea: The proof idea is to refuse to be fooled by the beginning of the story. Go to the last real choice first. At that point earlier speeches are already sunk, so the player compares the remaining payoffs. Once the later action is known, earlier players can reason backward about what their first move will cause.

Mathematical move: Backward induction assigns a value to each final branch, chooses the best later action, and carries that continuation value back to the previous node. Subgame perfection keeps this logic honest by checking equilibrium behavior after every possible history.

Why it matters: This proof move turns dynamic games into disciplined reasoning about credibility. It explains why threats, promises, bargaining positions, and entry deterrence depend on later incentives, not just announcements.

Where it breaks: The argument changes if players cannot observe earlier moves, if there is uncertainty about payoffs, if commitment devices alter the future choice, or if the game is repeated so reputation and future punishment enter the payoff comparison.

Proof-reading move: Read the proof from the end of the tree, not from the dramatic beginning. At the last decision point, earlier promises have already become history, so the player compares only the remaining consequences. Once that later choice is pinned down, the previous player can forecast it. The proof is a chain of forecasts carried backward through the tree.

Student trap: The common trap is to believe a threat because it sounds severe at the start. A threat matters only if the threatening player will still want to carry it out when the time comes. Another trap is to solve the initial path but ignore off-path nodes. Subgame perfection asks what would happen after histories that are not supposed to occur, because those histories determine whether the original threat is credible.

Rebuild check: To rebuild the proof, mark every terminal payoff, solve each final choice by ordinary payoff comparison, replace that node with its continuation value, and move one step earlier. Repeat until the first move is reached. If any later action is justified only by a past announcement rather than by the later payoff comparison, flag it as a noncredible threat unless a commitment device changes the available choice.

Why the move is legitimate: Solving the last choice first is legitimate because earlier costs and speeches are sunk once the later decision node is reached. At that later node, the player compares the continuation payoffs that remain. Carrying that value backward is valid because earlier players can foresee later rational behavior in the modeled tree. The hidden requirement is that players observe the relevant history and understand the payoff tree. If information is missing or commitment changes the later menu, the backward step must be rebuilt.

Why future punishment can change today's temptation

Ordinary claim: Cooperation can survive repeated conflict only when the future loss from punishment is large enough to outweigh the one-time gain from cheating.

Minimal setup: The same strategic problem repeats. Players can condition later behavior on earlier behavior, and future payoffs are discounted by a factor that says how much tomorrow matters today.

Proof idea: The proof compares two lives from the current moment forward. In one life the player cooperates and keeps the future relationship. In the other the player cheats once, earns a current gain, and then faces punishment. Cooperation is stable only if the first life is worth at least as much as the second.

Mathematical move: A repeated payoff stream is v0 + delta v1 + delta^2 v2 + ... . The cooperation inequality says the value of staying on the cooperative path must be at least the value of deviating now plus the discounted punishment path.

Why it matters: This result explains how time can become an incentive device. It connects repeated games, folk-theorem logic, implicit cartels, and one-shot deviation checks without pretending cooperation appears automatically.

Where it breaks: The argument fails when the future is too weak, cheating is hard to observe, punishment is not credible, players are short-lived, or outside institutions change the continuation value.

Proof-reading move: Read the proof as a comparison between two continuation stories starting today. Story one keeps cooperation and earns the cooperative stream. Story two takes the tempting deviation now and then lives under whatever punishment the strategy prescribes. The discount factor translates future rewards and losses into today's terms, so the proof turns patience, monitoring, and punishment into one incentive comparison. The proof is not about kindness; it is about whether the threatened future loss is large enough at the exact moment cheating is tempting.

Student trap: The common trap is to say repeated interaction supports cooperation without checking the punishment path. The future disciplines behavior only if cheating is noticed and if the punishment is itself rational later. A second trap is to treat the discount factor as a moral trait called patience. In the proof it is a weight on future payoffs, and a small change can flip the inequality.

Rebuild check: To rebuild the proof, write the value of staying cooperative, then write the value of one deviation plus the punishment continuation. Compare those two streams at the moment of temptation. Then run the same logic on the punishment behavior: when the future arrives, do punishers actually want to punish? If monitoring is noisy, add the signal structure before claiming the inequality proves cooperation.

Why the move is legitimate: Comparing continuation streams is legitimate because today's action changes not only today's payoff but also the future path the strategy prescribes. Discounting translates those future consequences into today's comparison. The hidden requirement is that future behavior can actually condition on today's action: cheating must be observed or inferred, punishment must be feasible, and punishers must prefer to carry it out when the time comes. Without those conditions, the inequality is only a story about discipline.

Why evidence changes beliefs only through type likelihoods

Ordinary claim: An observed action teaches something about a hidden type only if different hidden types would choose that action with different likelihoods.

Minimal setup: There is hidden information, a prior belief over possible types, an observable action or signal, and a receiver who changes behavior after seeing the signal.

Proof idea: The proof asks which hidden worlds would have made the observed signal likely. If high-quality sellers often offer a warranty and low-quality sellers rarely do, seeing a warranty should raise belief in high quality. If both types offer the same warranty, the observation carries no separating force.

Mathematical move: Bayes rule says posterior probability is proportional to prior probability times likelihood of the observed signal under that type. Perfect Bayesian reasoning then checks whether each type actually wants to send the signal assigned to it.

Why it matters: This result keeps information models honest. It prevents the reader from treating signals as magic proof and shows why signaling, screening, cheap talk, and adverse selection need both belief updating and incentive checks.

Where it breaks: The argument is weak when the signal is off the equilibrium path, when imitation is cheap, when priors are unsupported, or when the model assumes belief updates without explaining which type would have produced the evidence.

Proof-reading move: Read the proof in two passes. First ask what each hidden type would probably do, because that gives the likelihood of the observed signal. Then update the receiver's belief using those likelihoods. Only after the belief is updated should you check the receiver's action. In a signaling proof, the sender's incentive check and the receiver's belief update must fit each other. Beliefs are not free decoration; they are generated by the proposed behavior whenever the observed signal is on the path.

Student trap: The common trap is to say the signal reveals the type because the story says so. A signal reveals only when different types have different incentives or costs for sending it. If low-quality and high-quality types can imitate each other cheaply, the observation may not separate them. Another trap is to invent off-path beliefs after the fact to make a proposed equilibrium work.

Rebuild check: To rebuild the proof, list the types, prior probabilities, proposed signals, and receiver actions. For each observed signal, ask how likely that signal is under each type, then update belief in words before writing symbols. Next check sender incentives type by type: does each type prefer the signal assigned to it? If either the belief update or the incentive check fails, the equilibrium story is not complete.

Why the move is legitimate: Bayesian updating is legitimate because an observed signal is evidence only through the behavior that different types would generate. The likelihood term connects the hidden type to the visible action. The hidden requirement is that the proposed strategy really makes those likelihoods meaningful. If every type would choose the same signal, the evidence has no separating force; if a type would rather imitate, the likelihoods used in the belief update are not supported by incentives.

Why different auction formats can produce the same expected payment

Ordinary claim: Under strong assumptions, auction formats that allocate the item in the same way can make bidders pay the same amount on average, even if the payment rule looks different.

Minimal setup: Bidders have private values drawn from the same environment, the allocation rule gives the object to the same type of bidder, bidders are risk neutral, and the lowest type has the same expected payoff across mechanisms.

Proof idea: The proof tracks incentives instead of surface rules. If the same value type has the same chance of winning in two mechanisms, then the payment schedule is pinned down by the requirement that nearby types do not want to pretend to be each other. Different auction language can hide the same incentive geometry.

Mathematical move: The envelope-style logic links a bidder's expected payoff change to the allocation probability. Once the allocation rule and the lowest type's payoff are fixed, expected payments are determined. The course version can be read as payment following from allocation plus incentive compatibility.

Why it matters: This result teaches a deeper market-design habit: do not compare auction formats only by their labels. Ask which allocation rule they create, which deviations they prevent, and which assumptions make the payment comparison valid.

Where it breaks: The result can fail with risk aversion, affiliated values, budget constraints, different reserve rules, asymmetric bidders, or richer information. The theorem is powerful exactly because its assumptions are doing real work.

Proof-reading move: Read the proof by ignoring auction labels at first. Ask what chance each value type has of winning, then ask what payments are needed so nearby types do not want to pretend to be each other. If two mechanisms give every type the same winning chance and the same payoff to the lowest type, incentive compatibility pins down the expected payment path.

Student trap: The common trap is to remember the theorem as first-price equals second-price. That slogan hides the conditions. The result is not about names; it is about allocation rules, type distributions, risk attitudes, and the boundary payoff. Another trap is to export the result to ad auctions or procurement without checking budgets, quality scores, reserves, repeated participation, and correlated information.

Rebuild check: To rebuild the proof, state the environment before doing any algebra: private values, symmetry, risk neutrality, independent draws, allocation rule, and lowest-type payoff. Then compare two formats by their allocation probability for each type. If the allocation probabilities match, follow the incentive-compatibility logic to expected payments. If one assumption changes, identify which part of the payment argument must be rebuilt.

Why the move is legitimate: Focusing on allocation probability is legitimate because incentive compatibility ties a type's payoff changes to how often that type wins. Once the allocation rule and the lowest type's payoff are fixed, the expected payment path has little freedom left. The hidden requirement is the clean auction environment: risk neutrality, comparable type distributions, and the same allocation rule. If bidders are asymmetric, values are correlated, or budgets bind, the allocation-to-payment argument no longer pins down the same revenue comparison.

Why everyone knowing a fact is weaker than common knowledge

Ordinary claim: A fact can be known by each person privately and still fail to coordinate behavior because people may not know that others know it too.

Minimal setup: Several players make choices that depend on what others will do. A fact or signal may be private to each player or publicly observed by all players.

Proof idea: The proof idea is the ladder of awareness. If I need your action to make my action safe, I need more than the fact itself. I need confidence that you know it, and often confidence that you know I know it. Public announcements can change behavior because they build this shared ladder.

Mathematical move: Common knowledge is recursive belief: everyone knows X, everyone knows that everyone knows X, everyone knows that everyone knows that everyone knows X, and so on. The recursion represents shared strategic certainty, not extra physical facts.

Why it matters: This result explains why communication, public signals, cheap talk, and coordination problems cannot be reduced to information delivery. The strategic effect comes from changing what people can rely on others understanding.

Where it breaks: The logic can fail when messages are not public, when players interpret the same message differently, when incentives make cheap talk unreliable, or when only a few layers of belief are needed rather than full common knowledge.

Proof-reading move: Read the proof by asking what each player needs to rely on about the others. If my action is safe only when you act, and your action is safe only when you believe I will act, the proof climbs a ladder of beliefs. A public signal works because it creates not just the fact, but shared evidence that everyone received the fact.

Student trap: The common trap is to say everyone knows the fact, so coordination should follow. Private knowledge can leave each person unsure about what others know, or unsure about what others think they know. Another trap is to confuse truth with publicity. The fact may be true, but the strategic problem is whether players can rely on others treating it as shared.

Rebuild check: To rebuild the proof, name the action that requires coordination and ask what belief makes that action safe. Then ask what belief about the other player's belief is needed, and keep climbing until the model's requirement is visible. If the result needs a public announcement, verify that the message is observed by all and known to be observed by all. If the message is cheap talk, separately check sender incentives.

Why the move is legitimate: Climbing the belief ladder is legitimate because the payoff from a coordinated action depends on what others do, and what others do depends on what they believe about everyone else. The recursion is not decorative; it represents the repeated dependence of my confidence on your confidence and your confidence on mine. The hidden requirement is publicness. If the message is privately delivered, unevenly interpreted, or strategically untrustworthy, the ladder may stop after only a few rungs.

Math walkthrough clinic

Dominance: the inequality is a universal comparison, not a vibe check

Dominance Inequality

Problem before math: A player has several moves, and one move looks bad. The danger is deleting it too quickly because it loses in the case that feels most likely.

Failed shortcut: The shortcut is to compare the moves under one opponent action and call the loser dominated. That fails because the opponent may choose a different action, and the deleted move might be useful there.

Plain-English equation reading: Read the dominance inequality as a row-by-row audit. Keep move s over move t only if s gives at least as much payoff as t against every possible opponent move, with a strict advantage somewhere.

Symbol by symbol: Read s and t as two candidate actions for the same player. Read the opponent action as the case being checked. Read the payoff function as the model's ranking device. The inequality must hold for each opponent case, not just for the case the analyst expects.

Worked numbers: If high price gives payoffs 4 and 2 against the rival's two moves, while low price gives 3 and 1, high price dominates low price because 4 is greater than 3 and 2 is greater than 1. If the second comparison were 0 versus 1, dominance would fail.

Why the math has to exist: The math exists because intuition is too eager to delete. A universal inequality forces the analyst to prove that a move has no strategic defense anywhere in the represented game before removing it from later reasoning.

Assumption check: Check that the opponent action set is complete, the payoffs are mapped correctly, and the comparison uses the same player in every row. If any rival action is missing, the deletion may be invalid.

Why this changes reasoning: The math lets the reader remove a move without first predicting the opponent. That is powerful precisely because the comparison survives every opponent action in the model.

Misuse repair: If you catch yourself saying the action is probably bad, stop calling it dominance. Keep the action alive and move to beliefs, expected utility, best responses, or rationalizability.

Transfer test: Use this test when you see a strategy deletion step in a paper or lecture. Ask: did the author compare every relevant opponent case, or only the convenient one?

Symbol trap: The trap is to read the inequality as one comparison rather than a family of comparisons. The opponent case is not decoration; it is the thing that must vary while the dominance claim keeps surviving.

Paper-reading use: In a paper, dominance is a license to remove an action before prediction. Read that license narrowly. If the author deletes a strategy, find the table, state, or opponent-action set that makes the deletion universal. If the deletion depends on probability language, the author has left dominance and entered belief-based reasoning.

Math walkthrough clinic

Expected utility: one number for a choice made before uncertainty resolves

Expected Utility

Problem before math: A player must choose now, but the payoff depends on a state they do not yet know. Looking only at the best possible outcome or the worst possible outcome throws away part of the situation.

Failed shortcut: The shortcut is to pick the action with the biggest payoff in one state. That fails because a rare jackpot and a common modest payoff should not be treated as equally likely.

Plain-English equation reading: Read the expected utility equation as weighted averaging. For each possible state, take the payoff from the action, weight it by how likely that state is, and add the weighted pieces.

Symbol by symbol: Read each state as one possible way the world could turn out. Read the probability as the weight placed on that state before choosing. Read the payoff as what the action gives in that state. The sum gathers those weighted pieces into one comparable number.

Worked numbers: If bidding gives payoff 90 with probability one third and payoff 0 otherwise, its expected payoff is one third times 90 plus two thirds times 0, which equals 30. A safer action worth 25 is worse under this calculation, even though it avoids the zero outcome.

Why the math has to exist: The math exists because choice happens before uncertainty is resolved. Without weighted averaging, a reader may chase the best possible ending, fear only the worst ending, or ignore how likely each ending is.

Assumption check: Check where the probabilities come from, whether the payoff numbers represent the same objective across states, and whether the chooser is being modeled as expected-utility maximizing rather than using another risk rule.

Why this changes reasoning: The equation turns a messy uncertain choice into a comparable quantity while preserving both payoffs and probabilities. That is why it reappears in Bayesian games, auctions, and screening.

Misuse repair: If the argument focuses on a vivid jackpot or vivid loss, rebuild the state table. Put each payoff beside its probability, then compare actions only after the weighted values are computed.

Transfer test: Use this test whenever a model chooses before hidden information is revealed. Ask: what are the states, what are the probabilities, and what payoff does this action produce in each state?

Symbol trap: The trap is to treat the average as if it describes one actual future. It does not. It is a before-the-fact comparison number built from many possible futures and their probabilities.

Paper-reading use: In a paper, use expected utility to audit risky choice claims. Find the states, the probability source, and the payoff in each state. If any one of those is vague, the expected-value conclusion is less solid than the formula makes it look. Also check whether the paper is assuming risk neutrality or a utility curve that already encodes risk attitude.

Math walkthrough clinic

Best response: the best move only after the outside behavior is fixed

Best Response

Problem before math: A player asks what to do, but the answer depends on what others do. A move cannot be called best in the abstract.

Failed shortcut: The shortcut is to rank a player's actions once and use that ranking everywhere. That fails because an action that is best against one opponent move may be terrible against another.

Plain-English equation reading: Read BR_i(a_-i) as a conditional instruction: after everyone else's actions are held fixed, look across player i's actions and keep the payoff-maximizing ones.

Symbol by symbol: Read BR as the best-response set, not always a single action. Read i as the player being tested. Read the outside action profile as fixed while player i compares their own actions. The answer is conditional on that outside behavior.

Worked numbers: If a firm earns 8 from producing high quantity when the rival produces low, and 5 from producing low quantity, high is the best response to low. But if the rival produces high and the payoffs switch to 1 for high and 4 for low, low is the best response to high. The same firm therefore has different best responses in different columns.

Why the math has to exist: The math exists because no strategic action is best in empty space. A choice becomes best only after the environment created by other players, beliefs, or histories is pinned down.

Assumption check: Check that the player has the listed actions available, that the outside behavior is really being held fixed, and that payoffs include everything the player cares about at that moment. If information is hidden, the fixed object may be a belief rather than a known action.

Why this changes reasoning: The math prevents the reader from treating strategy as a personality trait. It makes every recommendation conditional on the environment created by other players and therefore forces the model to state the outside behavior.

Misuse repair: If a model says an action is optimal without saying against what, supply the missing condition. Ask whether the same action remains best under a different rival move, belief, or later history.

Transfer test: Use this test when a paper says an agent optimally responds. Ask: optimal against what belief, opponent action, continuation path, or information set?

Symbol trap: The trap is to forget the minus-i object. BR_i is not a personality label for player i; it is a response to the other players' fixed actions, beliefs, or continuation path.

Paper-reading use: In a paper, every optimal-response claim should answer optimal against what. Look for the fixed environment before trusting the maximization. If the environment changes, the best-response calculation must be run again. This is especially important when the fixed object is a belief or continuation value rather than a visible opponent move.

Math walkthrough clinic

Nash equilibrium: every local best-response check passes at once

Nash Equilibrium

Problem before math: A proposed outcome may look plausible when viewed from outside, but each player still has their own private temptation to move away from it.

Failed shortcut: The shortcut is to choose the outcome with the highest total payoff or the most natural story. That fails because a prediction must survive each player's unilateral deviation check.

Plain-English equation reading: Read the Nash condition as a loop closure. For every player, the action assigned to that player must be inside the best-response set created by the other players' assigned actions.

Symbol by symbol: Read the candidate action profile as the whole proposed prediction. For each player, hold the other players' assigned actions fixed. Read the inequality as saying the assigned action gives at least as much payoff as any unilateral alternative.

Worked numbers: If both firms choose low price, and either firm would earn more by switching to high price while the other stays low, low-low is not Nash. If neither firm can improve by changing alone from high-high, then high-high passes the Nash test even if both would prefer another coordinated outcome. The comparison is local to one player's move at a time.

Why the math has to exist: The math exists because a prediction must survive inside each player's own incentives. A story can sound plausible from outside but fail because one player has a profitable private escape.

Assumption check: Check which deviations are allowed, whether the game is one-shot or dynamic, and whether players know the payoff structure. Nash does not test coalitions, histories, hidden types, or welfare unless those are added separately.

Why this changes reasoning: The equation changes prediction from a story about what should happen into a checkable stability claim. It also explains why equilibrium can be inefficient without being internally inconsistent.

Misuse repair: If you are tempted to call the equilibrium good, rewrite the claim as a deviation test. Then ask a separate welfare question instead of loading moral meaning into Nash stability.

Transfer test: Use this test whenever a model reports an equilibrium. Ask for each player: holding everyone else fixed, what exact deviation would improve their payoff, and which deviations are outside the model's scope?

Symbol trap: The trap is to read one player's inequality as the whole equilibrium. Nash requires the same style of no-profitable-deviation check for every player covered by the model.

Paper-reading use: In a paper, an equilibrium claim should come with a candidate profile and a deviation set. Ask which deviations were checked, whether the equilibrium is unique, and whether the author separately argues that this equilibrium is reached or selected. If welfare or learning is claimed, demand a separate argument beyond the Nash inequalities.

Backward induction: today's threat is judged by tomorrow's incentives

Backward Induction

Problem before math: A player threatens or promises a future action, and the current player reacts to that announcement. The key question is whether the future action would still be attractive later.

Failed shortcut: The shortcut is to take the announced threat as real because it changes current behavior. That fails when the threatener would not want to carry it out after the history reaches that point.

Plain-English equation reading: Read V(node) = max_action V(next node) as solving the tree from the end. At each decision point, replace the branch with the value of the best continuation available to the player moving there.

Symbol by symbol: Read each node as a decision point in the tree. Read the max operation as the mover choosing the best available continuation at that node. Read the value assigned to the node as the payoff that earlier players should expect from that point onward.

Worked numbers: If entry leads the incumbent to choose fight for payoff -1 or accommodate for payoff 2, the future incumbent chooses accommodate. The entrant should reason using 2 as the continuation, not the announced fight payoff. The earlier threat changes the story only if it changes that later comparison.

Why the math has to exist: The math exists because time lets early speech and later incentives diverge. Backward recursion prevents an announced plan from counting unless it would actually be chosen when the later moment arrives.

Assumption check: Check the order of moves, who observes what history, and whether the later player can commit in advance. If commitment or outside reputation changes the later payoff, the tree must include it rather than treating the simple backward-induction result as final.

Why this changes reasoning: The recursion makes credibility visible. It strips away future actions that sound scary today but would not be chosen tomorrow when the acting player actually compares continuations.

Misuse repair: If a threat seems powerful, jump to the node where it is carried out. Compare the remaining actions there. Only feed the threat backward if it wins that later comparison.

Transfer test: Use this test when a model contains threats, promises, bargaining delays, or exit options. Ask: what would the acting player choose at the final decision node after earlier speech is sunk?

Symbol trap: The trap is to treat the max at a future node as if it were chosen by the earlier player. The mover at that later node chooses the continuation, so the earlier player must anticipate that later self-interest.

Paper-reading use: In a paper, backward induction tells you to inspect timing before accepting a commitment story. Find the last real choice, solve it, and only then move to earlier claims about deterrence, bargaining, or promises.

Math walkthrough clinic

Discounting: cooperation survives only if the future is heavy enough

Discounted Payoff Sum

Problem before math: A player can gain by cheating today, but cheating may destroy future cooperation. The issue is not whether punishment exists; it is whether the future loss is large enough.

Failed shortcut: The shortcut is to say repeated interaction supports cooperation. That fails when players are impatient, the future is short, punishment is too weak, or cheating is not observed.

Plain-English equation reading: Read the discounted sum as today's value of a stream of payoffs. Current payoff counts fully; each later payoff is multiplied by another power of delta, the patience factor.

Symbol by symbol: Read delta as the weight placed on the next period relative to this one. Read later powers of delta as making farther future payoffs count less today. Read the sum as today's value of a whole future path.

Worked numbers: If cheating gives an extra 5 today but causes a loss of 2 every future period, patience matters. With delta near zero, those future losses barely count. With delta near one, the repeated future loss can outweigh the one-time gain because many later losses are valued almost like current losses. The same punishment path can therefore work for patient players and fail for impatient players.

Why the math has to exist: The math exists because future consequences are not all equally powerful. A punishment ten periods away cannot be treated like a payoff now unless the model states how much the player values the future.

Assumption check: Check whether the horizon is finite or indefinite, whether cheating is observed, whether punishment is credible, and whether the discount factor is high enough for the claimed cooperation.

Why this changes reasoning: The formula turns vague future consequences into a comparison. It tells the reader when cooperation, cartel discipline, or bargaining patience can actually be incentive-compatible rather than merely socially plausible.

Misuse repair: If the argument says cooperation follows from repetition, ask for the incentive inequality. The repeated relationship matters only through the discounted comparison between deviation and continuation, plus the credibility of punishment.

Transfer test: Use this test in repeated-game arguments. Ask: what is the one-shot gain from deviation, what is the future punishment path, and how large must delta be for restraint to make sense under the monitoring assumptions?

Symbol trap: The trap is to see many future terms and assume they are automatically large. The powers of delta may shrink those future payoffs sharply, especially when the player is impatient or punishment starts late.

Paper-reading use: In a paper, discounting should force a threshold claim. Ask how patient players must be, when punishment begins, and whether the future path is credible. Repetition is not the proof; the discounted inequality is. A serious repeated-game argument should identify the one-shot gain, the continuation loss, and the delta range that makes restraint rational.

Bayes rule: beliefs move because evidence favors some hidden types over others

Bayes Rule

Problem before math: A player observes an action or signal and needs to infer what hidden type may have produced it. The observation is useful only because some types are more likely to produce it than others.

Failed shortcut: The shortcut is to update toward the type that feels most vivid after the signal. That fails because updating must compare how likely the same signal is under each possible type.

Plain-English equation reading: Read Bayes rule as reweighting. Start with prior belief in a type, multiply by how likely this signal is if that type is true, then divide by the total chance of seeing the signal.

Symbol by symbol: Read the prior as belief before the signal. Read the likelihood as how often a type would produce that signal. Read the denominator as the total chance of seeing the signal. The posterior is the reweighted belief after evidence arrives.

Worked numbers: Suppose high quality is 40 percent likely. High quality sends an expensive signal 75 percent of the time, and low quality sends it 25 percent of the time. The high-quality weight is .4 times .75 = .30; the low-quality weight is .6 times .25 = .15, so the posterior high-quality belief is .30 divided by .45, or two thirds.

Why the math has to exist: The math exists because evidence is comparative. A signal supports a type only relative to how likely that same signal would have been under other types in the model.

Assumption check: Check that the prior is stated, the possible types are exhaustive enough for the model, and the signal likelihoods are justified by incentives or data rather than inserted to get the desired posterior.

Why this changes reasoning: The equation disciplines belief changes in Bayesian games, signaling, and perfect Bayesian equilibrium. Beliefs become responses to modeled evidence instead of free narrative choices or convenient story patches.

Misuse repair: If a signal feels persuasive, ask whether it is actually more likely under the claimed type. If every type would send it, Bayes' rule gives little reason to move beliefs.

Transfer test: Use this test when an action is interpreted as information. Ask: which types could have produced this signal, and how likely was the signal under each type?

Symbol trap: The trap is to update from the signal's story rather than from its likelihood under each type. The denominator matters because it counts all the ways the same signal could have appeared.

Paper-reading use: In a paper, Bayes rule should make belief updates accountable. Find the prior, the likelihood for every relevant type, and the observed signal. If the likelihoods are asserted rather than derived from incentives or data, mark the posterior as fragile. For strategic signals, ask why each type would or would not choose the observed signal.

Math walkthrough clinic

Auction expected payment: bid choice mixes price and chance of paying

Auction Expected Payment

Problem before math: A bidder chooses a bid before knowing whether they win. The bid changes both the chance of winning and the amount paid if winning, so price and probability cannot be separated informally.

Failed shortcut: The shortcut is to look only at the payment if the bidder wins. That fails because a very high payment may be attached to a very small or very large winning probability, and incentives depend on both.

Plain-English equation reading: Read expected payment as payment-if-win times probability-of-winning. In richer auction formulas, the same idea is hidden inside integrals or expectations, but the primitive is still price times chance.

Symbol by symbol: Read the payment conditional on winning as the price in the event that allocation happens. Read the winning probability as how often that event occurs under the bid. Their product is the expected payment before knowing whether the bidder wins.

Worked numbers: If bidding 10 means paying 10 with a 20 percent chance of winning, expected payment is 2. If bidding 18 means paying 18 with a 70 percent chance of winning, expected payment is 12.6. The higher bid raises both the chance and the expected payment, so the bidder must compare extra allocation value against extra expected cost.

Why the math has to exist: The math exists because bids change both prices and chances. Looking only at the price paid after winning misses the strategic value of raising or lowering the probability of winning.

Assumption check: Check the auction format, what determines allocation, whether payment occurs only on winning, and whether quality scores or reserve prices change the probability or payment calculation.

Why this changes reasoning: The calculation explains bid shading and revenue comparisons. A bidder trades off a better chance of allocation against a higher payment burden before knowing whether payment occurs.

Misuse repair: If an auction explanation focuses only on the winning bid, split the rule into allocation probability and conditional payment. Then recompute expected payment from both pieces before making a revenue or bidding claim.

Transfer test: Use this test for auctions and ad auctions. Ask: what event triggers payment, what is paid in that event, and how does the bid change the probability of that event?

Symbol trap: The trap is to read payment as the posted price alone. Expected payment is conditional payment times the chance that the condition occurs, and both pieces can move when the bid changes.

Paper-reading use: In a paper, auction payment formulas should be read as incentive machinery. Separate allocation probability, conditional payment, and bidder value before accepting a revenue, truthfulness, or bid-shading claim. If quality scores or reserve prices enter, treat them as changing either the chance of winning, the payment if winning, or both.

Math walkthrough clinic

Common knowledge: coordination needs public recursion, not just shared facts

Common Knowledge Recursion

Problem before math: Several players privately know the same fact, but they may not know whether the others know it too. Coordination can fail because the fact is not publicly anchored at every level of reasoning.

Failed shortcut: The shortcut is to say everyone knows the fact, so coordination should follow. That fails when each player doubts whether others know, or doubts whether others know that others know.

Plain-English equation reading: Read E, KE, KKE, and the continuing chain as levels of publicness. E is the fact; KE says everyone knows it; KKE says everyone knows everyone knows it; the dots say the chain never stops.

Symbol by symbol: Read E as the event or fact. Read K as a knowledge operator: who knows that event. Read repeated K's as higher-order knowledge, such as everyone knowing that everyone knows. Common knowledge means the chain keeps going.

Worked numbers: If two traders both hear a private rumor, each may still wonder whether the other heard it. A public announcement changes the structure because each knows the other heard the same announcement and knows the other can reason from that shared event. The announcement changes the belief hierarchy, not necessarily the first-order fact.

Why the math has to exist: The math exists because coordination can fail even when the fact itself is shared privately. Players may need confidence about other players' confidence before acting together on a risky shared move.

Assumption check: Check whether the signal is public, whether all players interpret it the same way, and whether the payoff problem actually requires coordinated beliefs rather than only private information.

Why this changes reasoning: The recursion explains why public announcements and shared awareness can change strategic behavior even when the underlying fact was already true for every individual player.

Misuse repair: If someone says everyone knows, ask which level they mean. A public announcement can matter because it upgrades private or mutual knowledge into a shared recursive anchor that players can safely use for coordination.

Transfer test: Use this test when coordination seems mysteriously fragile. Ask: is the fact merely true, privately known, mutually known, publicly announced, or common knowledge?

Symbol trap: The trap is to stop at the first K. Knowing the fact is not the same as knowing that others know, or knowing that others know that others know. Coordination may need the chain.

Paper-reading use: In a paper, common-knowledge claims should identify the public event or protocol that creates shared recursion. If the information is private, noisy, or interpreted differently, the common-knowledge conclusion is too strong. Ask whether coordinated action needs first-order knowledge only, or whether it needs confidence that others are reasoning from the same public fact.

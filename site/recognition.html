Recognition Clinic

A diagnostic layer for fresh problems. Start with the situation in front of you, ask the simple test question, then jump into the concept, primitive, and transcript evidence that fit.

Recognition clinic

When the problem is really about ranking outcomes

Reader situation: You are looking at a story where nobody has made a strategic move yet. The hard part is simpler and earlier: one person has several possible outcomes, and you need to say which outcomes they would rather have.

Diagnostic question: Can I describe what this person wants before I describe how anyone reacts to anyone else?

Decision cue: Use this card when the story has a chooser, outcomes, uncertainty, or tradeoffs, but no other strategic actor is yet changing the payoff. The cue is a missing preference scale, not a missing equilibrium concept.

First-principles test: Start by separating desire from strategy. If changing another player's move is not the main issue yet, the right first move is to build a scale of better and worse outcomes. Preferences give the ordering; utility turns that ordering into numbers only when numbers help compare or calculate.

Mathematical handle: The mathematical object is an ordering or payoff map. In plain language, it is a disciplined way to say this outcome is preferred to that one, and sometimes by how much for the calculation at hand.

Wrong diagnosis cost: If you call this a game too early, you will invent opponents or incentives that are not doing work. The model then hides the basic question of what the person values and how uncertainty should be counted.

Worked recognition: In the transit example, first list what the rider ranks: shorter time, lower price, fewer transfers, reliability, or comfort. Only after those wants are represented should the analyst ask whether agencies, taxpayers, or rival riders create strategic dependence.

False friend: Do not treat a payoff number as a physical measurement like height or weight. In many game theory uses, the number is a bookkeeping device for choices, not a direct measure of happiness.

Transfer check: In a new paper, stop at the first objective function and ask whether it represents one actor’s ranking or an interaction among actors. If it is only one actor, diagnose preference and utility before strategy.

Hidden primitive to spot: The hidden primitive is preference before strategy. Look for language about costs, benefits, reward, welfare, discomfort, risk, or satisfaction, then ask whether the paper has turned those pressures into an ordering. The diagnosis is right when the central missing object is a scoreboard for one chooser, not a reaction pattern among several choosers.

Boundary case: Stop using this card when another actor's choice changes the payoff ranking itself. If the rider's value depends on a transit agency's pricing rule, a rival route's congestion, or another player's threat, the problem has moved from preference representation into strategic representation. The preference scale still matters, but it is no longer the whole diagnosis.

Recognition clinic

When the problem is really about drawing the situation correctly

Reader situation: You are given a messy interaction and feel tempted to solve it immediately. But the real bottleneck is that the order of moves, available actions, and information are not yet clear.

Diagnostic question: Would the answer change if I wrote the same story as a table instead of a tree?

Decision cue: Use this card when the facts are messy because timing, observation, or available actions are unclear. The cue is that changing the diagram from a table to a tree would change what counts as a sensible solution.

First-principles test: Ask what each player knows when they choose. If everyone chooses without seeing the others' current move, a table may be enough. If choices unfold over time, or later players observe earlier moves, the tree matters because timing can create or destroy credible threats.

Mathematical handle: The mathematical object is a representation of players, actions, timing, information, and payoffs. The math matters because different representations preserve different facts about the same story.

Wrong diagnosis cost: If you skip representation, you can solve the wrong game perfectly. A simultaneous table can make later threats look fixed, while a tree can expose that the later player would not carry out the announced action.

Worked recognition: In an entry-threat story, write the entrant’s choice first and the incumbent’s response second. If the incumbent chooses after seeing entry, credibility lives at that later node, so a tree is the honest representation.

False friend: Do not solve a game before checking whether the representation erased timing or information. A table can hide a threat that a tree exposes as not credible.

Transfer check: When reading a model, ask what the author preserved: simultaneous actions, observed histories, private information, or later decision points. If the representation hides the disputed feature, the solution cannot settle the real question, even when the algebra after that point is correct.

Hidden primitive to spot: The hidden primitive is preserving the right information. A table, tree, or information set is not a drawing choice; it is a claim about what facts matter. Spot this card when the disagreement is about who moves first, who observes what, or whether a later response can condition on an earlier action.

Boundary case: Stop using this card once the representation is no longer disputed. If players, actions, timing, information, and payoffs are already clear, the next question is not how to draw the game but which solution test fits it. Representation is the doorway; staying there too long can delay the dominance, equilibrium, or belief check that actually answers the model. The useful handoff is a clean table, tree, or information map.

Recognition clinic

When the problem is really about ruling out unreasonable moves

Reader situation: The game has too many possible choices, and some of them look foolish no matter what the other side does. The useful work is not predicting the final outcome yet; it is shrinking the possibility space.

Diagnostic question: Is there an action that is worse than another available action under every relevant comparison?

Decision cue: Use this card when the main task is removing actions before predicting a final outcome. The cue is a comparison that does not need a probability over the opponent because one action loses across every relevant case in the represented game.

First-principles test: Look for a move that can be beaten without needing a precise prediction of the opponent. Dominance and iterated deletion are pruning tools: they remove choices that cannot be justified by any sensible belief about the other player's behavior.

Mathematical handle: The mathematical lever is an inequality across payoffs. If one action always gives less than another against the same outside behavior, the weaker action can be deleted from serious consideration.

Wrong diagnosis cost: If you call an unlikely action dominated, you smuggle beliefs into a pruning rule. That can delete strategies that later matter for equilibrium, signaling, or rationalizability, and it makes the reduced game look more certain than the original evidence allowed.

Worked recognition: In a pricing game, do not delete low price merely because the rival is probably calm. Compare low price and high price against every rival action. If low price wins against an aggressive rival, dominance has failed.

False friend: Do not confuse unlikely with dominated. A move is not dominated merely because it sounds bad; it must lose under the comparison the model is actually making.

Transfer check: In a proof, find the exact set of outside actions used in deletion. If the author has not compared every relevant case, move from dominance language to belief, best-response, or equilibrium language.

Hidden primitive to spot: The hidden primitive is safe pruning. The sign that this card fits is not that an action seems silly; it is that one comparison beats it across the whole represented environment. Look for words like always, never, regardless, delete, eliminate, or cannot be rationalized, then inspect whether the paper earned those words with every-case comparisons.

Boundary case: Stop using this card when the argument needs a belief about what the opponent will probably do. At that point the paper is no longer pruning by dominance; it is using best response, rationalizability, or equilibrium reasoning. Keeping the distinction matters because dominance claims are stronger and should not borrow certainty from informal expectations. A deleted action should lose by comparison, not by narrative taste.

Recognition clinic

When the problem is really about mutual consistency

Reader situation: Each player's best move depends on what the other players do. A recommendation that sounds good for one person may collapse once the others are allowed to respond.

Diagnostic question: If everyone heard the proposed prediction, would anyone want to change their own move?

Decision cue: Use this card when each player’s best move depends on what others do and the question is whether a proposed prediction holds together. The cue is a unilateral deviation check against a fully specified candidate outcome.

First-principles test: Hold the other players' choices fixed and ask whether each player is doing the best they can from their own point of view. Equilibrium is not moral approval and not group happiness; it is a no-one-wants-to-unilaterally-move test.

Mathematical handle: The mathematical object is a fixed point of best responses. In everyday terms, the prediction points back to itself: each part of the prediction gives the other parts a reason to stay in place.

Wrong diagnosis cost: If you confuse equilibrium with welfare, you will reject stable bad outcomes or praise inefficient ones. The model’s prediction claim and the analyst’s welfare judgment become mixed together, so the reader cannot tell what the theorem actually proved.

Worked recognition: For aggressive pricing, freeze one firm at aggressive and ask whether the other wants to switch. Repeat in the other direction. If neither wants to move alone, the outcome can be equilibrium even if both prefer coordinated softness.

False friend: Do not read equilibrium as good, fair, efficient, or inevitable. It can be bad for everyone, and the course uses it because it is a disciplined prediction test, not because it is a welfare judgment.

Transfer check: When a paper says equilibrium, ask which deviations are allowed. If only one player can move alone, do not infer efficiency, fairness, uniqueness, convergence, or stability against coalitions.

Hidden primitive to spot: The hidden primitive is mutual best response. Look for a proposed outcome that must survive many local checks at once. This card fits when the paper's real work is not ranking actions in isolation but closing a loop: each actor's choice makes the others' choices sensible, and the others' choices make the first actor's choice sensible.

Boundary case: Stop using the plain equilibrium card when timing or hidden information is doing the hard work. A static Nash check may miss whether threats remain credible later or whether beliefs are consistent after observed behavior. In those cases, keep mutual consistency as the primitive but move to subgame-perfect, Bayesian, or perfect-Bayesian language. The diagnosis should follow the missing consistency check.

Recognition clinic

When the problem is really about time and credibility

Reader situation: A player promises, threatens, delays, bargains, or plans to act later. The central question is whether a future action would still make sense when that future moment arrives.

Diagnostic question: Would the player still want to carry out the announced plan after reaching the point where the plan is supposed to happen?

Decision cue: Use this card when promises, threats, bargaining offers, delays, or future punishments appear. The cue is that today’s statement must be tested at a later decision point where the speaker may face different incentives.

First-principles test: Reason from the end backward. A future threat only matters if it is optimal when the future decision point is actually reached. Backward induction and subgame perfection make the model check promises at the moment they must be honored.

Mathematical handle: The mathematical lever is recursion over time: solve the later choice, then use that answer when solving the earlier choice. The later self constrains what the earlier self can credibly claim.

Wrong diagnosis cost: If you accept future speech at face value, you can predict deterrence from empty announcements. The model then gives early words more force than later incentives justify and misses the credibility problem the tree was meant to expose.

Worked recognition: For an incumbent threat, jump to the node after entry and compare fight with accommodate. If accommodate is better there, backward induction says the entrant should not treat the earlier threat as credible without commitment.

False friend: Do not accept a threat just because it changes today's incentives. If carrying it out tomorrow would hurt the threatener, the model treats it as empty unless another mechanism repairs credibility.

Transfer check: In any dynamic model, identify the last real choice and solve it first. Then work backward. If a claimed strategy fails at a later subgame, the early prediction needs repair.

Hidden primitive to spot: The hidden primitive is later incentives disciplining earlier speech. Spot this card when a statement today matters only because someone expects an action tomorrow. The key is to ignore the dramatic announcement and jump to the future node where the actor must actually choose. The primitive appears in threats, bargaining deadlines, reputation promises, and staged product or entry decisions.

Boundary case: Stop using pure backward reasoning when the later decision maker lacks perfect information about what happened or what type they face. Then the future node cannot be solved only by looking at the tree; beliefs have to enter. Credibility remains the concern, but the right tool may become perfect Bayesian equilibrium or signaling. Also stop when there is no later choice to test; then the issue may be commitment technology, not sequential reasoning.

Recognition clinic

When the problem is really about the future disciplining the present

Reader situation: The same players interact repeatedly, so today's selfish move may change tomorrow's treatment. The current action is also a signal about how the relationship will continue.

Diagnostic question: Is a short-run temptation being restrained by the value of future cooperation?

Decision cue: Use this card when the same players meet over time and today’s action changes future rewards or punishments. The cue is a tradeoff between immediate temptation and continuation value.

First-principles test: Compare the one-time gain from deviating with the future loss from being punished or losing cooperation. Repetition matters when future consequences are large enough to change what is rational today, not merely because the relationship continues.

Mathematical handle: The mathematical lever is discounting: future payoffs are counted, but usually with less weight than immediate payoffs. Cooperation can survive only when the discounted future is strong enough to outweigh the immediate temptation.

Wrong diagnosis cost: If repetition is treated as automatic cooperation, finite horizons, weak monitoring, low patience, and noncredible punishment disappear. The repeated-game claim becomes a slogan rather than an incentive calculation.

Worked recognition: For a tacit cartel, name the gain from secretly cutting price today and the loss from future price wars. Cooperation is plausible only when the discounted future loss is large enough to beat the current gain and the rival can actually detect and punish cheating.

False friend: Do not assume repetition automatically creates cooperation. If the end is known and close, or players care little about the future, the repeated game can unravel back toward one-shot behavior.

Transfer check: When a paper invokes future discipline, locate the deviation payoff, punishment path, monitoring assumption, and discount factor. If one is missing, mark the cooperation claim as incomplete rather than treating repetition as the mechanism by itself.

Hidden primitive to spot: The hidden primitive is present value of future consequences. This card fits when today's behavior is being held in place by tomorrow's reward or punishment. Look for a comparison between a one-time gain and a stream of future losses, even if the paper calls it reputation, relational contracting, collusion, or long-run discipline. The repeated-game clue is a current action changing a continuation value.

Boundary case: Stop using this card as soon as the future cannot be observed, enforced, or valued enough. Repetition alone is not a mechanism; the mechanism is detected deviation plus credible continuation consequences. If those pieces are absent, the right diagnosis may return to one-shot equilibrium or move into private-information monitoring. A long relationship without a credible punishment is just repeated exposure, not discipline.

Recognition clinic

When the problem is really about hidden information

Reader situation: One side knows something the other side does not: a cost, value, quality, patience level, or outside option. The visible action is partly a choice and partly evidence about the hidden fact.

Diagnostic question: Am I trying to predict behavior when players disagree about what kind of person or situation they are facing?

Decision cue: Use this card when one side knows a value, cost, type, quality, or outside option that others cannot directly observe. The cue is that visible behavior also serves as evidence, because observers must infer what kind of player would choose that action.

First-principles test: List the possible hidden types and ask what each type would do. Then ask how observers should update their beliefs after seeing an action. Hidden information turns strategy into a joint problem of choosing and interpreting.

Mathematical handle: The mathematical object is a belief over possible types, combined with payoffs conditional on those types. Bayes' rule enters when observed behavior changes which hidden type seems more likely.

Wrong diagnosis cost: If you ignore hidden types, you may treat a signal as a simple statement or a belief as arbitrary. The model then misses imitation incentives and unsupported posterior beliefs.

Worked recognition: For a warranty, ask which seller types find the warranty cheap. If reliable sellers can afford it and unreliable sellers cannot profitably imitate, the warranty can move buyer beliefs. If all types mimic, it cannot separate quality.

False friend: Do not treat a belief as a guess with no discipline. In Bayesian games and signaling settings, beliefs must be tied to the possible types, observed actions, and equilibrium logic.

Transfer check: In a new signaling or Bayesian model, list types, priors, observed actions, and imitation checks. A belief update is disciplined only when those pieces explain why the action came from some types more than others.

Hidden primitive to spot: The hidden primitive is belief over hidden cases. This card fits when the visible action has two meanings at once: it changes payoffs and it changes what observers think is true. Look for type, value, cost, quality, posterior, adverse selection, screening, or any claim that behavior reveals something not directly observed.

Boundary case: Stop using this card when the relevant fact is already public to all players at the time of choice. If no one is uncertain about type, value, action history, or signal meaning, belief updating is not doing the work. The model may still involve incentives, but the private-information diagnosis would add machinery without explaining anything. Use this card only when an observer must learn from behavior or messages.

Recognition clinic

When the problem is really about rules shaping incentives

Reader situation: The main object is not a player choosing inside fixed rules, but the rules themselves: an auction format, market institution, ad slot system, contract, or communication protocol that changes participant incentives.

Diagnostic question: Would changing the rules change what people reveal, bid, produce, or hide?

Decision cue: Use this card when the rules themselves are the object: an auction, ranking system, contract, market protocol, or communication rule. The cue is that changing the rule changes what participants reveal or choose, even when their private values stay fixed.

First-principles test: Treat rules as machines for translating private motives into observable behavior. A good mechanism makes the desired behavior individually sensible; a bad one rewards hiding, shading, collusion, or misleading signals even if the designer announces a better goal.

Mathematical handle: The mathematical lever is incentive compatibility: the rule should make the intended action line up with each participant's own payoff calculation. Auctions, screening, and ad markets are different settings where that alignment is the design problem.

Wrong diagnosis cost: If rules are treated as neutral background, the analyst misses how allocation and payment rules create strategic responses. A mechanism can fail because it rewards hiding, shading, collusion, or low-quality signaling.

Worked recognition: In an ad auction, separate the bid, quality score, allocation rule, and payment rule. The platform’s goal matters only through the private calculations advertisers make under those rules, because advertisers respond to expected payoff rather than to the platform’s stated objective.

False friend: Do not judge a rule only by the outcome it asks for. The question is whether self-interested participants have a reason to produce that outcome when the rule is actually used.

Transfer check: For any mechanism, write the rule as input to outcome: private information and actions go in, allocation and payments come out. Then ask whether each participant’s best response produces the intended result.

Hidden primitive to spot: The hidden primitive is incentive alignment through rules. This card fits when the analyst is not merely predicting behavior under fixed rules but choosing the rule that turns self-interest into useful behavior. Look for allocation, payment, ranking, contract menu, reporting rule, reserve price, or truthfulness language. The mechanism clue is a designer changing consequences so private optimization produces a public target.

Boundary case: Stop using this card when the rules are fixed background rather than the object being evaluated. If the paper never asks how changing the rule changes bids, reports, effort, or information, then mechanism design may be too broad a diagnosis. Use ordinary equilibrium, private information, or payoff analysis inside the given rule instead. Do not call every institution design; require a live rule-choice question.
